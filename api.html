CompanionConnect API

For Hytale mod developers who want their companion plugin to coexist with Scruby

This page is a technical reference. If you are a player looking for gameplay instructions, see the main page.

What this is

Other Hytale companion mods can coexist peacefully with Scruby. Scruby's AoE skill targeting (Healer-AoE, DPS-Burst, Tank-Taunt, etc.) automatically skips entities from any plugin that follows the convention below. No registration, no runtime handshake, no plugin dependency is required for the basic case.

If you want the inverse - your own targeting should skip Scrubys - Scruby ships a small read-only Java facade you can call.

Easiest path - role naming only

Pick any name for your companion's NPC role and include the substring _CompanionConnect somewhere in it. That is the entire requirement.

Examples that match:

MyMod_Wolf_CompanionConnect
Awesome_Pet_CompanionConnect_Aggressive
SomeMod_Companion_CompanionConnect_Stationed

As soon as your plugin is loaded alongside Scruby, Scruby's AoE skills will leave your entities alone. Vanilla Hytale roles do not contain this substring, so there is no risk of false positives on regular mobs.

Optional - query Scruby from your code

To make your own skills skip Scrubys, add Scruby's JAR as a compile-only Gradle dependency. Use the latest release from CurseForge.

// build.gradle
dependencies {
  compileOnly files('libs/ScrubyCompanion-vX.Y.Z.jar')
}

Then in your skill or targeting code:

import org.example.plugin.ScrubyCompanionAPI;

if (ScrubyCompanionAPI.isScrubyCompanion(store, ref)) {
    continue; // do not target a Scruby
}

compileOnly means the JAR is only used for compilation - it is not bundled into your final mod artifact. At runtime, the actual Scruby JAR is loaded from the server's mods folder.

Available methods

  • isScrubyCompanion(store, ref) - returns true if the entity's NPC role name contains Scruby_.
  • isCompanionConnectNpc(store, ref) - returns true if the role name contains _CompanionConnect.
  • getScrubyOwner(ref) - returns Optional<UUID> of the owning player, for live registered Scruby companions only.
  • getConventionSuffix() - returns the literal convention string "_CompanionConnect".

The facade is read-only and side-effect-free. If Scruby is not on the server, the owner-lookup returns Optional.empty() rather than throwing.

What the protocol does NOT do

  • It does not modify direct auto-attack damage. That is governed by Hytale's NPC-Role attitude system, which is configured in the role definitions themselves.
  • It does not differentiate between same-owner and different-owner companions in PvP scenarios.
  • It does not publish lifecycle events (spawn, despawn, level-up) for other plugins to subscribe to.

These are deliberate omissions. Extensions are possible if there is real cross-mod demand.

Reflection alternative (no JAR dependency)

If your mod must work standalone (without Scruby installed), use reflection instead of a compile-time dependency:

try {
    Class<?> api = Class.forName("org.example.plugin.ScrubyCompanionAPI");
    boolean isScruby = (boolean) api
        .getMethod("isScrubyCompanion", Store.class, Ref.class)
        .invoke(null, store, ref);
    if (isScruby) continue;
} catch (ClassNotFoundException scrubyNotInstalled) {
    // Scruby is not on this server - nothing to skip.
} catch (Exception ignored) { }

This way your plugin compiles and runs without Scruby, and only activates the integration when Scruby is present.

FAQ

Do I have to coordinate with the Scruby developer?

No. Just pick a role name with the convention substring and you are done. There is nothing to register and no API key to obtain.

Will this break if I run my mod without Scruby installed?

The role-naming path has no runtime dependency at all - your mod runs unchanged whether Scruby is loaded or not. The optional Java API has a compileOnly dependency, so your final mod artifact does not include Scruby. If Scruby is missing at runtime and your code calls ScrubyCompanionAPI directly, you will get a NoClassDefFoundError; use the reflection alternative if that matters to you.

Can my companion attack a Scruby anyway?

Yes - direct auto-attack damage between companions is not blocked by this protocol. That behavior lives in Hytale's NPC-Role attitude system. If you want symmetric peace, configure your roles' attitudes accordingly in your own role definitions.
